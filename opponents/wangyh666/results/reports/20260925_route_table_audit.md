# 41 条路线表审计：13 + 28 精确成立，且**没有"落错组"**

> 2026-09-25。`SESSION_STATE.md` §9.3.2 的待办（来源 `claims.md` H10，
> 出自主 `master-engine-v4` 的自述）：**"41 条路线 = 13 经典 + 28 商店特化，
> 我们的 41 条是否也这么分组？有没有商店对落进了错的组？低成本、可核实。"**
>
> 结论：**分组精确成立；"落错组"这个问题在本血缘内不存在，而且静态上不可判定。**

工具：`scripts/route_audit.py`（从 `main.py` 的 base85+zlib 内嵌块里解出路线表，
不 import agent——import 会跑完整 1 MB 构建）、`scripts/route_compare.py`（与 8 个同血缘对手对拍）。

## 1. 分组：**精确命中**

```
routes: 41   ids: 0..12, 100, 101, 103..128      （102 缺号）
```

| 组 | ids | 条数 |
|---|---|---|
| 经典 V39 | 0 – 12 | **13** |
| `EXP240` 商店特化 | 100 – 128（去 102） | **28** |

⇒ **13 + 28 = 41，与 `master-engine-v4` 的自述逐字相符。** 每条 tape 长度都是 719。

## 2. 但"41 条"是名义上的：**64 个商店对只映射到 27 条**

| 事实 | 数值 |
|---|---|
| 商店对（有序，含同店） | **64**（= 8×7 异店 + 8 同店；与 `world_split.py` 的"64 个商店世界"对上） |
| 被商店表引用到的不同 route id | **27** |
| **从未被任何商店对引用** | `0–12`（13 条经典）、**`100`** |
| 单个 route 覆盖最多的商店对 | **`105`：21/64 = 33%** |
| 其次 | `107`：5、`126`：5、`103`：3、另有 7 条各 2 |

三条读法：

1. **`_R108_SHOP_ROUTES.get(shops, 100)` 的兜底 100 在这 64 个世界里永远不会命中**
   ——商店表对 64 个对全部覆盖。所以 `100` 是"未知商店对"的兜底，不是常用路径。
2. **经典 13 条在新路由下是死代码**：走 `EXP240` 分支时用 `_R108_SHOP_ROUTES`，
   走 `V39` 分支时用 `_R110_OLD_SHOPS`。**41 条里实际能被 EXP240 路由选中的只有 27 条。**
3. **`105` 一条吃掉三分之一的世界。** "41 条商店特化路线"这个说法容易让人以为分辨率是 64，
   实际是 27，且高度集中。

## 3. "有没有落错组"：**在该血缘内不存在，且静态不可判定**

### 3.1 与 8 个同血缘 agent 对拍 —— **0/64 分歧**

| sibling | 商店对 | 与 `main.py` 的分歧 |
|---|---|---|
| `guruv4`（= H10 那条声称的出处） | 64 | **0/64** |
| `guru`（v3） | 64 | **0/64** |
| `v56` / `v55` / `prvsiyan` / `pipe16` / `hybrid2965` / `tetsutani_cha22` | 各 64 | **各 0/64** |

⇒ 这张商店表是**整条血缘逐字节共享的**，不是我们本地引入的。**没有"我们抄错了"这回事。**

### 3.2 为什么"落错组"静态上问不出来

我原本打算用"这条 tape 到底卖不卖那家店的招牌货"当判据。**这个判据是空的**：

```
r101 sells = [CARROT, EGG, FERTILIZER, MELON, MILK, STRAWBERRY, TOMATO, WHEAT, WOOL]
r103 … r126  全部相同
```

**41 条 tape 卖的东西完全一样**（同样的 9 个品类）。所以"特化"不在**品类选择**上，
而在**时序**上——那么"这条路线配这家店是否合理"就没有静态参照物，只能实测。
